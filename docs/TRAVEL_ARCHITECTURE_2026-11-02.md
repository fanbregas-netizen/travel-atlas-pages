# Footprint Map × Travel Atlas — 双层旅行地图产品架构

> 2026-11-02。以用户上传的原始 `footprint map` 文本与两张手绘 visual 为最高产品定义，现有 V4 作为主地图视觉和星标交互基线。这里区分“已实现”和“待接入”，不能把原型交互冒充完整 AI 或后台服务。

## 1. 两张手绘图，不是同一张页面

- **图 2：Footprint Map 主页面**。地理地图 + 黄色星标 + 悬浮 Brief + 拼贴式相册/内容模块。接收来自微信公众号、小红书、Bilibili、YouTube 等平台的链接/文字/图片/视频，记录为什么想去。原有四向 SVG 气泡归属主地图单个星标的点击状态，原则上不改视觉语言。
- **图 1：Travel Atlas 子页面**。由路线规划进入，按一条自然弯曲的路径排列 **D1/D2/D3...** 旅行日及地点气泡；内容沿时间/路线叙事。旅行计划提供日期、出发地、目的地及选点顺序。照片与社交内容作为单站内容，不把子页面简单理解成另一版地图标记。
- **主子页返回**：主地图 →「规划路线」→ 子页；子页任一站 →「地图星标」→ 主地图原星标；旅行结束后的内容仍留在原星标媒体库中。

## 2. 数据边界（禁止破坏用户收藏）

```
Footprint Map (index.html / atlas-orbit.js)
 └─ IndexedDB private-travel-footprints-v1 / places   ← 原有个人收藏主数据
       id, title, lat, lng, note, date, photos, videos, references, starred ...
                    │ 仅读取，不迁移、不覆盖
                    ▼
Travel Atlas (journey.html + journey.css + journey.js)
 └─ IndexedDB travel-atlas-journeys-v1 / plans         ← 独立的个人路线数据
       id, title, startDate, endDate, origin, destination,
       stops: [{placeId, day}], updatedAt
```

- 收藏坐标使用 WGS84，导航发往高德时使用境内 WGS84→GCJ-02 转换。
- 高德导入工具 amap-import.html 在同一个 GitHub Pages 源域名中，位置审核合格后写入主收藏库。**未定位的 339 个候选不能谎称都已导入。**
- 页面不向公共仓库上传用户照片、Brief、原始 Excel/JSON 或 API Key。
- 本地 IndexedDB 不跨浏览器/网站域名同步；因此用户需在常用 Safari 内打开。需主动使用既有 ZIP 备份功能。

## 3. 本次完成的可运行架构

- `index.html`：保留 V4 地图/黄星/四向 SVG 现有体验，加「规划路线」入口；支持 `?openPlace=<id>` 从子页返回原星标。
- `journey.html`：子页双栏结构与 iPhone 响应式布局，基于用户手绘的弯曲路线 + D1... 各自气泡。
- `journey.js`：读取原有收藏、搜索加入站点、调整顺序、分配日期、显示 Brief 与两张照片预览、链接导航和返回星标，保存/读取/导出/导入路线 JSON。
- `journey.css`：与已认可 V4 兼容的低干扰中性视觉；子页重点在路线和卡片节奏，非原有主地图重新设计。
- AI 素材：一键整理地点文本、备注、日期、原有社交链接，复制交给 ChatGPT/Kimi 生成详细行程。
- 示例模式：3 个明确标注的虚拟站点用于验收形态，不能误写入真实个人收藏。

## 4. 尚未完成、不能伪装已完成的能力

1. **自动读取社交平台文章全文/图片**：需要用户授权、平台 API/合法抓取策略与失败处理；当前只读取地点内已保存的 Brief/链接。
2. **AI 自动优化路线与真实时间表**：需要服务端模型调用、导航距离/通行时间、用户确认及错误处理；当前是可编辑的顺序/分天视觉路书及 AI 输入整理。
3. **真实地图上绘制道路轨迹**：当前 SVG 是手绘式旅行叙事路径，不是道路导航折线。每站可打开高德导航。
4. **自动关联手机旅行后的照片/视频**：Web App 无法绕过 iOS 相册/定位授权自动读取用户所有照片；可做显式选择照片与位置/时间核对，未来可用原生 App 权限建立自动化候选匹配。
5. **跨端私密同步与多人分享**：现存浏览器本地库未具备身份验证、远端加密存储、冲突合并等体系。
6. **339 条高德收藏的真实地理编码和导入**：受原始 Excel 缺失经纬度限制，须在可信的服务或用户设备完成地址坐标解析与审核；未经审查绝不注入虚假坐标。

## 5. 核心验收序列

1. 打开 Footprint Map，地图与星标正常，既有 V4 SVG 气泡没有变化。
2. 点击「规划路线」，打开 Travel Atlas 子页，仍能读取该浏览器已收藏地点。
3. 选择 3 处地点，选择开始/结束日期和出发地/目的地，调整顺序、分配 D1/D2/D3，点击生成。
4. 子页出现弯曲的路线轨迹和对应地点卡片，备注、照片、链接正确关联，手机竖屏可阅读。
5. 点击卡片「地图星标」，返回主地图定位到原收藏；点击「高德导航」尝试唤起导航。
6. 保存路线，刷新后从「已保存路线」恢复；导出 JSON，再导入后站点、日期、顺序保留。
7. 不可更改原有 Brief、星标、照片、视频，不能把演示数据写入真实库。
