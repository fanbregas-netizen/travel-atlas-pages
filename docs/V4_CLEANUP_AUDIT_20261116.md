# Footprint Map V4｜代码与 UI 清理审计（第一轮）

**日期：2026-11-16，工作分支：`refactor/v4-clean-ui-20261116`**

## 边界与结论
- 本分支的第一步只整理 CSS 的存放方式，**不宣称解决了动画、排版或浏览器流畅度**。
- 原始 `main`、正式 Pages 首页、已验收模块及用户数据均不删除或覆盖。任何删除需确认文件没有运行时引用并通过回归。
- 本轮提取 32 个内嵌样式块（共 312,245 字符）到与首页同级的 `legacy-inline-cascade.css`；原顺序、每条 CSS 规则、相对资源路径原样保留。首页文件由 471,203 字符缩至 157,787 字符。这是**结构清理，不是冲突清理**。
- 按文本逐段核对：**32/32 内容一致**；不表示真机视觉已经一致。

## 代码结构发现（截至 V4 .19c）
- 首页原有 **32 个内嵌 CSS 块（约 312 KB）+ 16 个外部 CSS + 19 个外部脚本**。单独源文件还存在不同版本连续覆盖。
- `.drawer-head` 在主页 HTML 的样式中涉及 21 处匹配，`#fpSearchSheet` 43 处匹配。重复选择器并非全部错误，但已经难以辨别最终规则的所有权。
- 15 个 `data-inline` CSS 快照中，有 **9 个与同名外部文件全文相同**；其余 6 个内容有差异，不能直接删掉或用外部文件替换。
- 运行时至少有 `#drawer`（收藏）、`#fpPlaceCard`（地点详情）、`#destinationCard`（普通 POI）、路线规划面板等不同入口。共用弹簧公式 != 共用输入事件、卡片尺寸与状态机。
- 当前 .19c 虽有弹簧函数，用户录屏仍未达到所需效果。此前浏览器测试主要检验 JS 数值、某个 DOM 的位移、自动化触控，**没有充分验证真实 Safari 画面的连续性及跨卡片视觉一致性**。

## 后续清理顺序（不得一次性删光）
1. **锁定视觉合同**：采用用户已确认的四屏验收演示稿为唯一视觉基准；记录眉头两行结构、各子项留白、图标位置、关闭按钮、收藏列表、路线选点状态；禁止另起一套设计。
2. **建立样式所有权**：针对收藏、地点、POI、路线四个真实 DOM 逐项找出最终生效 CSS，删除被覆盖且不再使用的规则；保留一个基础 token 文件和各组件单一入口，而不是 v15/v16/v17/v18/v19 无限追加。
3. **整理物理交互状态机**：一个统一的 spring 参数/solver；每种 sheet 由真实 pointer/touch 输入驱动，不允许普通 POI 独立使用 display/visibility 切换而跳过位移动画；搜索历史在内容渲染完成后触发真正可见的回弹。
4. **恢复产品完整性**：保留个人数据、地图单一渲染、影像、攻略、路线、中文界面与已确认的唯一黄星。不要从旧版重新拼 UI。
5. **验收门槛**：同一 iPhone 宽度前后对比图 + 真实时间轴帧采样 + 手指拖拽轨迹 + JS/网络错误 + 375/390/430px 自动化回归；最终 Safari 真机触感仍须用户验收。
